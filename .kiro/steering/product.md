# 产品：代码守灵堂

代码守灵堂把“删除废弃代码”转化为一场由证据裁决的数字葬礼。Kiro 删除演示模块后，项目自动立碑；测试失败时旧代码以幽灵状态“诈尸”；修复回归且测试通过后，墓碑才显示安息。

## 核心承诺

- Kiro 不只是开发工具，也是运行机制的一部分：Spec 负责意图，Skill 负责葬礼流程，Hooks 负责确定性事件。
- “安息”必须由测试通过证明，不能由动画或文案假装。
- “诈尸”是可预期的回归揭示，不是需要掩盖的演示故障。
- 公开页面只展示元数据；源码永不成为墓志铭或上传内容。
- 线上站点明确标注回放，本地录屏展示真实 Hook。

## MVP 边界

- 只处理 `demo-src` 下由 Kiro Agent 删除的 `.mjs` 文件。
- 只展示一个可控故事：旧模块被删除、消费者断裂、Bugfix 后安息。
- 不做函数级删除、通用仓库扫描、账号系统、数据库或云端代码分析。

## 成功标准

评委在一分钟内能够回答三个问题：谁删了代码、为什么它诈尸、什么证据允许它安息。
